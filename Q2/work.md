
# AX 레볼루션 퇴고 워크플로우

각 단계는 **AI 작업 / 사람 검수 / 검수 기준** 세 가지로 구성된다. ★★는 필수 검수, ★는 강력 권장, 무표시는 선택적 검토. 전체 실행은 `/revise-chapter` 가 Phase별 게이트와 함께 관리한다.

---

## Phase A — 이해 (순차)

### 1. 구성·사례 통합 정리 ★

**AI:** `/manuscript-outline` — 단락별 핵심 주장 + 본문 사례(인물·기업·수치·인용)를 한 패스로 추출.

**검수:**
- AI가 누락한 사례를 한 번 훑어 보강.

**기준:** 이후 모든 검증의 입력원. 여기서 누락된 사례는 팩트체크에서도 누락된다. 본문을 빠르게 스크롤하며 "이 인물·수치도 잡혔나?" 만 확인.

### 2. 분석용 시각화

**AI:** `/manuscript-mindmap <outline> analysis` — outline을 Markmap/Mermaid 마인드맵으로 변환.

**검수:** (선택) 마인드맵이 챕터 구조와 일치하는지 시각적으로 확인.

**기준:** 편집자(작가)용 분석 도구일 뿐. 잘못돼도 본문 영향 없음.

### 3. 논증 흐름 점검 ★

**AI:** `/manuscript-flow` — 단락 간 연결, 주장-사례 균형, 회수되지 않은 선언 표시.

**검수:**
- "회수되지 않은 선언" 항목별로 작가 의도 변경인지 누락인지 결정.
- 약한 연결 중 의도된 단절(예: 화제 전환)을 ⚪로 표시.

**기준:** AI가 흐름을 잘 잡지만 *작가가 의도적으로 끊은 곳* 까지 일탈로 보는 경향이 있음. 작가만 의도를 안다.

## Phase B — 검증 (병렬 가능)

이 Phase의 5개 검사는 서로 독립적이라 **동시 실행** 한다. Phase 종료 후 게이트에서 모든 ★★ 검수 카운트를 한 번에 확인.

### 4. 팩트체크 ★★

**AI:** `/manuscript-factcheck` — reference의 ⚠️/🔴/🟡 항목을 섹션별 병렬로 web 검증. 결과를 reference 파일에 누적.

**검수 (필수):**
- ✅ 정확 분류 중 *맥락이 다르게 인용된 경우* 5~10개 샘플링 재확인.
- ⚠️ 부정확 항목의 모든 수정안 작가 승인 후 본문 반영.
- 실명 인물·기관에 대한 부정적·논쟁적 주장은 명예훼손 관점에서 한 번 더 확인.

**기준:** "출처 수치가 맞으니 ✅" 는 함정. 출처는 맞아도 본문이 잘못된 일반화로 끌어다 쓰는 경우가 가장 흔한 사실 왜곡.

### 5. 인용체크 ★★

**AI:** `/manuscript-citecheck` — 직접 인용·근접 인용을 web과 비교해 표절 위험 표시.

**검수 (필수):**
- 🔴 표절 위험 판정 *전수* 검토 — 진짜 표절인지 작가 결정.
- 🟡 의역 분류도 한 번 더 검토 — AI가 "의미는 같으니 OK"로 본 게 실은 너무 비슷할 수 있음.
- 출처 표기가 모호한 인용에 정확한 출처 채우기.

**기준:** AI의 표절 판정 정확도가 가장 낮은 영역. 의역과 표절의 경계는 작가만 결정.

### 6. 가상사례 명시 확인 ★★

**AI:** `/manuscript-fiction-check` — reference의 🔵 사례가 본문에서도 "가상" 명시되었는지 결정론적 검증.

**검수 (필수):**
- 🔴 누락 항목별로 명시 문장 추가.
- *"가상" 단어 존재* 가 아니라 *독자가 실재로 오인할 가능성이 사라졌는지* 가 진짜 기준 — 가상 사례 섹션을 한 번 통독.
- 가상 사례 *안에* 실명 회사·인물이 섞이지 않았는지 확인 (AI가 잘 놓치는 부분).

**기준:** 가상 사례 안에 진짜 회사·인물명이 들어가면 별 검증 없이 통과함. 작가가 통독 필수.

### 7. 챕터 간 교차 일관성 (사실·용어) ★

**AI:** `/manuscript-crosscheck` — 두 챕터의 용어 정의, 인물 표기, 반복 주장 정합성 보고.

**검수:**
- 용어 정의 불일치별로 어느 쪽이 정본인지 결정.
- 인물 표기 변이는 통일 결정.
- 반복 주장은 한쪽으로 몰지 분담시킬지 결정.

**기준:** 충돌 발견 시 작가의 책 구조 의도에 따라 결정. AI는 검출만, 결정은 사람.

### 8. 전체원고 톤·일관성 ★★

**AI:** `/manuscript-tone` — 챕터의 voice·어조·서사 결이 [AX레볼루션_통합원고.md](AX레볼루션_통합원고.md) 와 일관되는지 검사. 문장 길이, 종결어미 분포, 강조·인용 빈도, 인칭 패턴, 수사 등 톤 시그니처 비교.

**검수 (필수):**
- 🔴 강한 일탈 *전수* 확인 — 의도된 변주인지 표류인지 결정.
- 챕터를 책 중간에서 무작위로 펼쳤다고 가정하고 통독 — "이 챕터만 다른 책 같은가" 직관 검사.
- 🟡 약한 일탈 중 5개 정도 샘플링.

**기준:** 통계 일탈 ≠ 잘못. 도입부 일화나 사례 위주 섹션은 의도적으로 다를 수 있음. 다만 책 전반의 핵심 voice 규칙(평어/경어, 1인칭 사용, 강조 패턴)에 어긋나면 수정. 작가의 voice 직관이 최종 판단.

## Phase C — 개선 (순차)

### 9. 트리밍 (중복·길이) ★★

**AI:** `/manuscript-trim` — 반복 단락, 약한 사례, 정보 밀도 낮은 구간을 컷·축약 후보로 표시.

**검수 (필수):**
- 모든 컷 결정은 작가가 직접.
- AI가 "약한 사례" 로 본 게 voice·리듬에 기여하는 경우 보존.
- 의도된 반복인지 중복인지 판단.

**기준:** 비문학에서 반복은 강조 의도일 수 있음. 굵게 강조된 문단은 컷 후보에서 일단 제외.

### 10. 스타일 개선 ★★

**AI:** `/manuscript-style` — 가독성·표현·어법을 다듬어 diff 형식 제안.

**검수 (필수):**
- 모든 diff 작가가 직접 보고 채택 여부 결정.
- voice 평준화 위험 — AI 제안 중 작가 고유 비유·리듬을 평균값으로 끌어내리는 것은 거부.
- 굵게 강조된 핵심 메시지는 의미 변경 금지.

**기준:** 스타일 스킬은 *선택지* 를 줄 뿐 정답을 주지 않음. 본문 자동 수정은 작가가 명시적으로 요청할 때만.

### 11. 주석 추가 ★

**AI:** `/manuscript-annotate` — 일반 독자가 어려워할 개념·용어에 각주 후보 제시.

**검수:**
- 채택 여부 결정 — 모든 후보를 다 달면 흐름이 끊김. 핵심 개념만 채택 권장.
- 한 섹션에 각주 5개 초과면 일부 제거.

**기준:** 본문에서 이미 풀어 설명된 용어는 ⚪ 로 분류되어 제외되지만 그래도 한 번 더 확인.

## Phase D — 마감

### 12. 레퍼런스 정리 ★

**AI:** `/manuscript-references` — 본문 ↔ reference 양방향 cross-check, 누락·고아 보고, 챕터말 레퍼런스 초안.

**검수:**
- 본문에 인용된 출처가 reference에 누락되었으면 추가.
- reference의 고아 항목(본문에서 사용 안 된 자료)을 삭제할지 본문 인용 추가할지 결정.
- 미해결 🔴/🟡 항목이 있으면 `/manuscript-factcheck` 재실행.

**기준:** 고아 항목은 의도적으로 남긴 자료일 수 있음. 삭제는 작가 결정.

### 13. 독자용 시각화

**AI:** `/manuscript-mindmap <outline> reader` — 챕터 부록용 정제 마인드맵.

**검수:** (선택) 독자가 한 페이지에 책의 골격을 파악할 수 있게 보이는지 확인.

**기준:** 분석용과 달리 사례를 다 넣지 않음. 깔끔함이 기준.
