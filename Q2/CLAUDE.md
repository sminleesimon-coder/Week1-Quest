## 작업 시 반드시 따라야 할 워크플로우

[work.md](work.md) 의 4 Phase 13단계가 1차 사양입니다. 핵심 구조:

- **Phase A (이해)** — outline → 분석 마인드맵 → 논증 흐름
- **Phase B (검증, 병렬)** — 팩트체크 ∥ 인용체크 ∥ 가상사례 명시 ∥ 챕터 교차 ∥ **전체원고 톤**
- **Phase C (개선)** — 트리밍 → 스타일 → 주석
- **Phase D (마감)** — 레퍼런스 → 독자 마인드맵

각 단계는 work.md 에 **AI 작업 / 사람 검수 / 검수 기준** 3-필드로 정의되어 있습니다. 단계를 실행하려면 work.md 의 해당 단계 명세를 읽고 그대로 따르세요.

### HITL 등급 — 사람 검수가 필수인 지점

- **★★ (필수 검수, 스킵 불가)** — 단계 4 팩트체크, 5 인용체크, 6 가상사례 명시, **8 전체원고 톤**, 9 트리밍, 10 스타일
- **★ (강력 권장 검수)** — 단계 1 outline, 3 논증 흐름, 7 챕터 교차, 11 주석, 12 레퍼런스
- **(무표시)** — 단계 2 분석 마인드맵, 13 독자 마인드맵

★★ 단계의 AI 산출물은 **작가 승인 없이 본문에 반영하지 않습니다.** 특히 스타일·트리밍 단계에서 작가의 voice를 평준화하지 않도록 *제안만* 하고 작가가 선택합니다.

### 슬래시 명령으로 실행

각 단계는 대응 슬래시 명령이 있습니다 (`~/.claude/commands/manuscript-*.md`). 전체 순차 실행:

```
/revise-chapter <챕터_경로> [reference_경로] [전체원고_경로]
```

오케스트레이터가 자동 짝짓기 후 Phase A→D 순차 진행, Phase 사이 게이트에서 ★★ 검수 카운트를 노출. 특정 단계만 빠르게 돌리고 싶으면 단위 명령(`/manuscript-factcheck`, `/manuscript-tone` 등)을 직접 호출.

### 작업 범위 제한

특정 단계만 지시받았다면 그 단계에 한정해 작업하고, 인접 단계로 임의 확장하지 마세요. 예를 들어 `/manuscript-factcheck` 만 실행 요청을 받았는데 스타일까지 손대지 않습니다.

## 레퍼런스 파일의 검증 규약

레퍼런스 파일들은 단순 출처 목록이 아니라 **검증 상태가 메타데이터로 인코딩된 작업 도구**입니다:

- `🔴` — 즉시 확인 필요 (수치·인용 정확성)
- `🟡` — 출처 보완 필요 (현재 익명/불명확)
- `🟢` — 확인 완료
- `⚠️` — 검증 미완료 (모든 미확인 항목의 기본 표시)
- `🔵` — 가상 사례 (팩트체크 대상 아님, 본문에 "가상" 명시 필수)

각 reference 파일 하단의 **"검증 우선순위 요약"** 섹션이 팩트체크 작업 순서를 결정합니다.

본문을 수정할 때 새로운 숫자·인용·인물을 추가하거나 기존 것을 변경하면, **해당 섹션의 reference 파일도 같이 갱신**해야 짝이 깨지지 않습니다. (단 `/manuscript-factcheck` 의 마커 갱신은 자동.)

## 본문 작성의 스타일 규약(원고에서 관찰됨)

- 굵게(`**...**`) 표시된 문단은 저자가 강조한 **핵심 주장/요약 문장**입니다. 스타일 개선 단계에서도 이 강조를 함부로 풀지 말 것. `/manuscript-style` 도 굵게 강조 문단은 의미 변경 금지.
- 섹션 헤더는 `## **5.1.2 ...**`처럼 굵게 감싸진 형식을 일관되게 사용 — 새 헤더를 추가할 때 동일 패턴을 유지.
- "**\[사례 추가\]**", "**\[4부 연결\]**" 같은 인라인 태그는 저자의 편집 마커입니다. 별도 안내 없이 지우지 마세요.
- 외래어/고유명사는 한글 표기 후 괄호로 원어를 병기하는 패턴(예: 에이전틱 AI(Agentic AI), 오케스트레이션(Orchestration))을 사용.

## 본문 자동 수정 정책

본문(`AX레볼루션_*.md`), 레퍼런스 파일(`reference_*.md`), 전체원고(`AX레볼루션_통합원고.md`)는 **작가의 명시적 승인 없이 자동 수정하지 않습니다.** 모든 단위 스킬은 *제안·보고서* 만 산출하고, 본문 반영은 작가가 결정합니다.

예외: `/manuscript-factcheck` 가 reference 파일의 ⚠️/🔴/🟡 마커를 검증 결과에 따라 🟢 로 갱신하는 동작은 정상 (사양에 명시).

## 응답 언어

본문이 한국어이고 사용자도 한국어로 작업하므로, 모든 분석·요약·편집 제안은 한국어로 합니다. 인용·고유명사·코드 식별자는 원어 그대로 보존합니다.
